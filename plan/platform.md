# 广度与平台

模拟器从单位扩到模块和效果表，然后是对战平台本身。单位基本支持之后，这里的顺序按
fight-coverage 按系统的贪心顺序重排。

## 栈

1. **单位科技，按系统排。** 一个系统是 `TechnologyGroupData` 的一个子类列表（附加武器、buff、
   装甲强化、对空攻击、索敌专精、导弹拦截、重生效果……）或科技的一个字段（`isInverseIsLockTarget`、
   `expChangeRate`）：实现它一次放行表里的所有成员，所以顺序按 fight-coverage 的
   "by system, greedily ordered" 排，而不是按单条理由；"by layout field" 说明剩下的距离几乎都
   落在单位科技上。依赖决定实际先后，贪心顺序只决定依赖允许的范围里先做哪个：
   - 附加武器里留地形的成员（燃烧弹、焦土冲击、黏油弹）和其它成员一起做，`RangeItemSystem`
     已经在了。
   - buff 科技复用塔损失、电磁冲击和地形已有的 `BuffManager`。

   每个系统先录每个成员至少一场探针；成员机制各不相同的系统（附加武器）按成员分 PR。沙虫、深渊、
   泰山和骇客的控制光束是单位，归 [units.md](units.md)。
2. **剩下的非科技拒绝。** 有护盾时导弹装置开火（护盾对导弹弹体做什么）、召唤和 buff 类战场技能
   落在有战场护盾的战斗里、单位编组的技能槽打建筑。各自只挡零星几回合，按它在 fight-coverage
   里独占的回合排进上一项的贪心顺序。
3. **平台。** `arena`、`shell --json` 和 `game` 后端。

## 语料打错的回合

verify-matches 列出的、模拟器打了却和 match 不一致的回合，是已经放行的系统里的分叉：发现就压到
栈顶，逐回合找到第一处分叉的原因、修掉，把这一回合由游戏录下钉进 `tests/corpus/fights/`，一个
原因一个 PR。

## 停车场

- **装备、军官和召唤物上剩下的按名拒绝。** 指向没读过的 `mech_type` 的装备和能量塔技能、生产线、
  效果未确认的装备字段、两个军官都设行军时间倍率、召唤或生产出来的单位带科技给的吸血维修护盾、
  行军单位带开战 buff、一个单位两层屏障。语料现在不被它们挡住。reopen_when：fight-coverage 的
  理由里出现其中之一。

- **移动行为（`IMoveBehaviour`）。** 技能代码里有几处直接改运动状态，代替 build 里"技能空闲，
  `AutoMoveBehaviour` 随之不再激活"；移动信标只能在技能代码里加分支。改成运动侧的 `MoveBehaviour`
  （自动或指令），收回技能对运动状态的直接写入。reopen_when：又一个机制要替换单位的移动行为。
