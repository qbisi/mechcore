# 部署阶段的可移动性

[English](mobility.md)

本文索引固定在 build 2259。它说明部署阶段哪些单位可以移动、什么能解除不可移动，
以及两者的证据。

状态按单位记录这个答案，字段是 `movable`；
[`state.md`](../spec/document/state.md#a-unit-carries-two-fields-a-layout-does-not)
定义该字段，[`action.md`](../spec/document/action.md#move_unit) 定义写它的决策。

## 规则

单位在它到场的那一回合可以移动，此后每回合都停在原地，除非有东西解除它。到场指的是
被购买、被增援卡发放，或在回合开始时交付——开局的部队和军官发的小队就是这样上场的。

三样东西能解除一个从更早回合留下来的单位：

| 是什么 | ID | 解除范围 |
| --- | --- | --- |
| 部署模块 | 装备 `13040001` | 穿戴它的单位，每个回合 |
| 高速引擎 | 科技 `1606` 兵蜂、`1611` 霸王、`1616` 凤凰 | 该单位类型的全部单位，每个回合 |
| 再部署 | 指挥官技能 `1000001` | 它指定的单位，本回合剩余时间内 |

再部署是部署阶段技能：它在战斗前改变局面，所以一个回合把它的槽位标为已使用，而不是
已释放。

## 游戏检查了什么

每一次记录下来的移动都经过 `TerritoryManager.CanMoveUnits`，它对每个单位调用
`CardElement.CanMovable()`，而后者只是一次比较：`mobilityState != Limit`。
`MobilityState` 有三个值：`Once`（0）、`Limit`（1）、`Free`（2）。

再部署的 `PAP_ReleaseCommanderSkill.ChangeMobilityState` 把 `Once` 写进它的目标，
并保留被它替换掉的状态，`UndoChangeMobilityState` 会把那个状态放回去。这部分是从
本 build 的代码里读出来的。

回合开始时是哪一处写入把状态设为 `Limit`、部署模块与高速引擎又在哪里写成 `Free`，
没有读出来：没有任何调用点出现 `CardElement.SetMobilityState`，说明这些写入被内联在
未被跟进的代码里。上面规则的这几部分依据的是下面的语料。

## 证据

本地观测集记录了 41 场对局共 3735 次移动。每一次移动的单位都是规则允许移动的：

| 为什么能动 | 移动次数 |
| --- | ---: |
| 本回合购买或被发放 | 2812 |
| 回合开始时交付 | 790 |
| 穿着部署模块 | 43 |
| 所属单位研究了高速引擎 | 40 |
| 本回合被再部署指定 | 50 |

"回合开始时交付"指的是编号不低于上一回合结束时单位分配器的那些单位。快照自带的
`roundCount` 分不开它们和上一回合买的单位：回合开始时交付的军官小队，读出来可能
已经是 1。

语料里没有一次被游戏拒绝的移动，所以它能说明规则不过严，不能说明规则不过松。一个
停在原地、没有被移动的单位，两种情况下都说得通。
