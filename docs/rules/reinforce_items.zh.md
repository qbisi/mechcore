# 增援卡牌

[English](reinforce_items.md)

从第二回合起，每一回合对局给双方发同样的四张卡，每一方拿一张。本文说明卡有哪五类、
拿一张会改变什么、以及它要花多少钱。目录本身是机器可读的，放在 `config/` 下。

证据是本机 Steam 安装里本地录下的排位录像，哪些录像可用由
`tests/grbr/README.md` 说明。

## 五类卡

| 类别 | 拿了它会改变什么 | 目录 |
| --- | --- | --- |
| 指挥官技能 | 技能加入 `battle_skills` | [`config/reinforce_items.yaml`](../../config/reinforce_items.yaml) |
| 装备 | 物品加入该方的 `equipment` | 同一个文件 |
| 军官 | 军官加入状态的 `officers` | 同一个文件，效果在 [`config/officers.yaml`](../../config/officers.yaml) |
| 单位 | 单位到场 | [`config/unit_reinforcements.yaml`](../../config/unit_reinforcements.yaml) |
| 先遣队 | 第 0 回合的开局，一支部队或一名专家军官 | [`config/advance_teams.yaml`](../../config/advance_teams.yaml) |

前三类给出的就是它们自己 ID 所指的那样东西，不存在第二层映射：拿了卡 `13030001` 就
加上装备 `13030001`，拿了卡 `1100001` 就把指挥官技能 `1100001` 放上面板。整个语料里，
38 张装备卡和 29 张指挥官技能卡把自己的 ID 放进了该方的下一份快照，26 张军官卡中有
24 张同样如此，两个例外是该方已经持有的军官。

这就是 `config/reinforce_items.yaml` 要带 `kind` 的原因：ID 本身说明了这是什么东西，
但没说明它属于三个字段中的哪一个。

单位卡是例外。它的 ID 命名的是卡而不是单位，所以它的表要写明它发放哪种单位、几个小队、
到场时是几级，以及最早能在哪一回合被发出。build 2259 没有任何一张卡混合两种单位。

## 开局

先遣队是同一种形状的东西，在第 0 回合选一次。26 个玩家位每一个都恰好选了一支，而且
每一个的第 1 回合阵容都正好是所选先遣队的单位列表。

两种东西共用这一次选择，[`config/advance_teams.yaml`](../../config/advance_teams.yaml)
同时收录它们。一支队伍发放五个单位的部队；一名专家改为授予它自己 ID 所指的军官，可选
的有 16 名：陆战队专家解锁陆战队并发放一个 3 级小队，补给专家每回合加 50，导弹专家把
两次导弹打击放上面板。

两者都会改变反应堆，更强的开局就是这样付费的。队伍的调整量从 -300 到 +700，专家的从
-600 到 +500：补给专家用 600 反应堆换每回合的收入，而快速补给专家用 500 换第 1 回合的
200 补给。

`BattleInfo.EnableAdvanceTeam` 在 13 场排位对局里全为真，在两场试验场对局里为假，所以
开局属于标准玩法，而不属于本格式不描述的某种模式。

## 一张卡要花多少钱

拿卡不是免费的。一张卡要么带自己的价格，要么按它的级别定价：

| 级别 | 价格 |
| ---: | ---: |
| 1 | 0 |
| 2 | 50 |
| 3 | 100 |
| 4 | 200 |

游戏自身数据里价格为 `-1` 表示由级别决定，抽取出来的表已经把它解出来，所以 `config/`
里每一行都写着账本可以直接扣的价格。导弹打击和护盾空投是 2 级、各 50，这条规则就是这样
发现的。

## 池子不会发什么

有两个过滤器决定一张卡是否会出现在表里。

`limitedScene` 指明一张卡属于哪些模式，只点名了其它模式而没有点名标准模式的卡会被排除。
空列表表示不作限制，而不是全部限制：战地修复就是这样列出来的，按另一种读法去理解，会
丢掉补给定价最需要的那个技能。

`scope` 说明增援池是否能发这张卡。只有一个取值表示可以，而语料对此毫不含糊：本地集合里
被选中的 120 张不同的卡，每一张都带着那个取值，而带其它取值的卡从来没有被选中过。有
两组我们熟悉的卡带着别的取值：

- 由蓝图研究出来的指挥官技能。十二个蓝图授予的技能全部被排除，其中包括粘性油弹、战地
  修复、移动信标和干扰信标。一方通过激活蓝图获得它们，
  [`config/economy.yaml`](../../config/economy.yaml) 里的 `grants_skill` 说明是哪一个。
- 属于开局而不属于池子的军官，也就是那 16 名专家；以及两条路径都到不了的军官，例如
  巨兽猎手和巨兽杀手。

这个过滤器不是普适的。单位卡和先遣队带着不同的取值，却照样会被发出，所以 `scope` 只对
"ID 即所授之物"的那三类读取，其余不读。这里被排除的军官仍然出现在
[`config/officers.yaml`](../../config/officers.yaml) 里，因为通过开局持有它的一方照样
享受它的折扣。

## 军官在加入列表之后还做什么

军官是唯一一类到场之后还会持续改变对局的卡。
[`config/officers.yaml`](../../config/officers.yaml) 记录了其中有效果的 81 个，形状
如下：

- 购买、解锁或升级单位的折扣，作用范围是一份明确的单位列表；或者研究科技的折扣，它不
  限定范围；
- 每回合收入的加成、仅第一回合的加成，或一次性发放的一笔；
- 摧毁巨型单位时战斗支付的赏金，这是唯一一种文档无法预测的效果；
- 军官发放的指挥官技能、装备或开局单位——这也是为什么拿一张军官卡可能会把一个技能放上
  面板。

## 表从哪里来

`scripts/extract_prices.py` 从同一个游戏 build 写出全部这些表。指挥官技能和装备目录是
配置数据容器不携带的两个 `level0` 对象，解析按 `ReinforceItemData` 的声明顺序遍历它们的
条目，而每一张可抽取的卡都共享这个结构。
