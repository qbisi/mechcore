# 落位

[English](landing.md)

本文索引固定在 build 2259。它说明棋盘把一个没有任何决策指定位置的单位放在哪里：
购买、增援卡的小队、开局的部队，以及军官的交付。battle 文档记录的是购买之后移动
结束的位置，所以它只为其余三种读这条规则。[`action.md`](../spec/document/action.md)
和 [`battle.md`](../spec/document/battle.md) 里回合开始时的交付都依赖它。

## 规则

新单位落在本方的主部署区，本地坐标 `x=[-300,300], y=[-310,-10]`，游戏在世界坐标系
里放置它，红方的区域是蓝方的区域转半圈。

1. 首选位置是区域中心，本地 `(0, -160)`，并把单位的角对齐到十米网格。角是中心减去
   一半占地，除以十、按四舍六入五取偶取整，再乘回去。因此占地为奇数个十米时落位会
   偏移五米，而这个偏移属于世界坐标：单位在两方都落在世界 `x = 5`，对蓝方是本地
   `5`，对红方是本地 `-5`。
2. 首选位置上没有东西与它重叠时，单位就落在首选位置。否则落在离它最近的空闲网格
   位置，搜索时外层按世界 `x` 升序、内层按世界 `y` 升序，并列时取最先找到的。

一个位置是空闲的，当且仅当占地完整落在区域内，且与区域上已有的单位、建筑或装置没有
正面积的重叠；边可以相接，护盾和导弹不参与判定。单位被旋转时，占地的宽和高互换。
一起发放的多个小队逐个落位，每一个都要避开它之前的那些。

## 游戏做了什么

`TerritoryManager.GetAvailiblePositionForNewActor` 取区域中心，围绕它构造元素的矩形，
用 `MapUtility.WorldToGrid` 对齐矩形的最小角，再把网格坐标乘以十。`WorldToGrid` 是
`FPoint.RoundToInt(value / 10)`，而 `FPoint.Round` 在小数部分小于一半时取整数部分、
大于一半时进位、恰好等于一半时取偶数。随后它向
`MapRegion.GetAvailiblePositionForElement` 要一个位置，并把上面那个作为首选。该方法以
十为步长遍历区域内每个网格位置，`x` 在外层、`y` 在内层，保留 `MapRegion.IsAvailible`
接受的那些，返回到首选位置距离严格最小的一个。`MapRect.Overlaps` 是严格比较，所以
相接的矩形不算重叠。以上都是从本 build 的 IsilDump 读出来的。

## 证据

在本地观测集里，有 341 个单位不是通过购买到场的：卡牌小队、开局部队和军官交付，其中
一部分要避开已经站在中心的单位。这条规则把这 341 个全部放在游戏放的位置上。用这条
规则替换录像里记录的落位之后，原生 oracle 检查的每一条决策和每一次部署仍然闭合。

跟踪录像里的每一次购买都落在规则给出的位置上：共 1632 次，每一次都是对照购买当时
该回合已经到达的局面读出来的。

区域被占满、没有空闲位置的情况，还没有观测到。
