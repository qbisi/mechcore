# 一方对另一方知道什么

[English](visibility.md)

本文索引固定在 build 2259。它说明游戏给一方关于另一方的什么信息，并把这个问题的两个
答案分开：客户端手里有什么，这是定下来的；界面给人看什么，这是没有定下来的。本平台
上的一局对局给玩家看什么不在这里，那是 [`cli.md`](../spec/mechcore/cli.md) 的 `match`
命名空间决定的——它是自己决定，而不是复现游戏，并且引用本文说明其中的差别。

## 客户端两边的数据都有

本地录像由打这局的客户端自己写出，它完整地带着双方每回合的快照。其中一份快照里就有
任何界面都不会给对手看的东西：另一方的补给、已解锁的单位、军官和科技。

`replay/grbr/2259_20260823--67294111_[你是蓬莱花仙]VS[crower].grbr` 的 `Seat` 是 1，
也就是由坐在 1 号位的玩家录下的，而它第 3 回合的快照给出了 0 号位的
`shop.unlockedUnits` 为 `[9, 24, 30, 1]`，旁边还有那一方的 `officers` 和 `supply`。
41 份跟踪录像中有 11 份录自 seat 0 或 1，每一份都带着双方。

所以隐藏是界面的工作，不是客户端的。玩家这台机器能回答关于对方的任何问题；游戏决定
的是画什么。

## 界面画了什么，本文没有定论

部署界面遮住对方那一侧，并在这一回合落定时揭开：`GameRiver.Client.FogOfWarController`
在玩家领地上显示和隐藏一个体积雾，并以 `OnTeamFinishDeploy` 作为隐藏它的时机。这是
从名字和调用边读出来的机制形状，达不到本目录对机制的证据标准：这里能用的反编译只有
调用图、没有方法体，所以雾遮住了什么、对谁遮，都没有闭合。

以下几条仍然未定，而且继续读下去也不会有答案：

- 双方都在部署时，一方能看到对方棋盘的哪些部分；其中一方结束部署后又有什么变化。
- 查看敌方单位时，是否会显示它的等级、装备和已经获得的科技。
- 一方拿到的增援卡是否会通知另一方；军官的效果除了体现在结果上，是否能在别处看到。
- 研究中心的蓝图、能量塔的技能和指挥官技能面板，在被使用之前是否可见。

每一条问的都是"画了什么"，所以每一条的关闭方式相同：打一局，在 adapter 采集状态的
同一时刻记录界面显示，然后比对。那是一次带观测的研究，不是读二进制，在它给出答案
之前属于 `work/research/`。

## 这件事为什么和文档有关

battle 文档记录的是有顺序的决策表，而玩家从来没见过这种东西：游戏展示的是棋盘，人靠
比较一个回合前后的棋盘来反推发生了什么。两份不同的决策表可以留下同一个棋盘，所以
有顺序的决策表比任何界面能给的都多：

- 先升级再装装备，和先装装备再升级，回合结束时站在那里的是同一个单位；
- 一个单位类型解锁、购买、研究科技、再卖掉，局面里留下解锁和科技，棋盘上什么也不留；
- 移动了三次的购买和一次放好的购买，最后站在同一个位置。

这些都是玩家没有理由按那个顺序去做的决策，也正因为如此，看棋盘通常足以反推出决策表。
但它们并非不可能发生，这个差别由平台决定，而不是由游戏决定。
